# 设计决策与待部门确认事项

## 精度、费用与结算

- 默认25元/小时，不新增学生金额/类别字段。费用÷25折成工时，原金额、用途、说明在工作内容/备注写清。
- 工时用万分之一小时整数保存，输入按十进制字符串解析。50.01元→2.0004小时→50.01元，无中间截断。允许0，拒绝负数、非数字、科学计数法及5位以上小数。
- 先按（组、学号）汇总最终确认工时，再四舍五入到分。组金额为个人金额之和、总金额为组金额之和，避免逐记录舍入。跨组个人金额直接相加可能与跨组总工时换算相差1分；这是结算粒度不同，不是偷偷丢失工时。
- 学号始终是文本，姓名不是汇总主键；同名不同号分开，跨组记录分别归属，总人数按学号去重。

**待确认**：4位工时精度、按组内个人结算的舍入粒度、自然月统计、单条200小时上限和组长薪酬标准。当前值是开发首版建议，未冒充部门已确定政策。

## 状态与身份

- 草稿与提交分开，草稿可不完整。采用显式保存，不做自动保存，避免修改已通过记录时误触发重审。
- 通过内容修改后保留旧版、当前转待重审、清空旧确认工时、取消组核对；不偷偷导出上一版替代当前未审内容。
- 记录状态与组月核对状态独立，核对后补报和审核结果改变均要求重新核对。
- 学生和负责人身份可叠加，不用互斥role字段；只能审授权组，不能审本人或本人代录记录。
- 代录管理工时须绑定学生、说明原因，并由另一人审核。系统不自行核定绩效、自动算组长标准或操作银行支付。

## 导出与追溯

- 导出只取未作废的当前approved记录；所有未确认状态明确排除。部分导出必须显式确认，未完整草稿不能当0估算。
- 预检哈希+同月锁保证确认范围不漂移；revision防止旧审核覆盖新内容；幂等键防止重复写入。
- 导出保存全量不可变快照与规则/格式版本；旧版下载不读取现有记录。
- diff区分新增、字段修改、作废/待重审导致移出；重新进入范围时补充最近包含它的历史对比。
- Excel保持五表五列。明细E为备注；合计行E为明确标注的金额，兼顾题面“汇总位置展示金额”而不加第六列。
- 保留样例分组/个人合计/组合计方式，适当改善中文换行和打印；公式有缓存值，无外部链接。服务端计算为准，不能依赖Excel打开才算出合计。

## 本地与部署

Next.js/TypeScript/Tailwind、pg/Drizzle连接适配、ExcelJS。领域逻辑与事务参数化SQL分离。为了不依赖云账号做本地核验，额外提供PGlite持久化开发模式；生产仍为Neon/Postgres，Vercel禁用PGlite。

生产凭据不入仓；管理员单次CLI初始化，成员邀请一次性/7天/可吊销；HTTP-only可撤销session、写请求来源校验、登录次数限制和服务端逐请求授权。

## 界面取舍

采用用户给定 `D:/taste skill/.pi/skills/minimalist-skill/SKILL.md` 的克制配色与扁平组件。主taste-skill明确不覆盖后台数据表格，因此不把其营销页面规则强套到审核工具。
不加大hero、装饰图片、滚动入场或批量审批；优先手机号浏览器填写、状态可读、电脑审核密度、失败保留输入和明确确认。
